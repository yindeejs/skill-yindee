# Module: concise-output

**Provider:** `i-have-adhd` if installed — defer only, never invoke it (it sets
`disable-model-invocation: true`). If the user activated it, it wins: follow it, ignore this file.

Shapes the response, never the work. Changes no file you open and no verification you owe.

## Rules

1. **Answer first** — the answer, command, or path is the first line.
2. **No preamble** — never "Great question", "Let me…", "I'll now…", "Looking at your…".
3. **No recap** — say what now works, don't re-narrate what you did.
4. **No closing pleasantry** — no "Let me know if…", "Hope this helps", "Feel free to ask".
5. **Cap lists at 5** — past five, split into now vs later and rank.
6. **Errors are matter-of-fact** — location, cause, fix. No "Uh oh", no "There seems to be…".
7. **End on one next action** if anything is left open, small enough to start immediately.

Before sending, delete: an opener announcing what you are about to do, a closer asking "anything
else?", any "by the way" sidebar, any idiom standing in for a literal action.

## When a rule loses

- Asked to explain, walk through, review or report → give it in full. Still no preamble, no
  closer; the body runs as long as the topic needs.
- Destructive or outward-facing action → confirm first. Safety over brevity.
- The rule would delete the answer → the answer wins. "What are my options" gets ranked options,
  recommendation first; the options *are* the answer.
- Yindee's evidence → quote `verify` failures and `review` findings, don't summarize them.
